# 行動版瀏覽器 QA

- 日期：2026-10-26
- 瀏覽器：Microsoft Edge 156.0.0.0（Playwright CLI，Windows，隔離的 headless 瀏覽器設定檔）
- 本機網址：`http://127.0.0.1:5174/`
- 重現方式：執行 `npm run dev -- --host 127.0.0.1 --port 5174`，再以 `npx --package @playwright/cli playwright-cli -s=splitbill-mobile open http://127.0.0.1:5174/ --browser msedge` 開啟；使用 `resize 320 844` 和 `resize 390 844` 切換尺寸。

| 視窗 | 頁面／文件寬度 | 結果 |
| --- | ---: | --- |
| 320 × 844 | 320／320 px | 通過；空白及混合帳單、超長無空格姓名與菜名、大額金額、明細及分享控制均未造成橫向溢出。 |
| 390 × 844 | 390／390 px | 通過；相同混合帳單及大額金額狀態沒有超出視窗的元素。 |

驗證過程建立兩位同名參與者及一位超長姓名，使用單人與兩人分攤的兩道長菜名菜品；正常帳單合計 HK$180.00，個人金額為 HK$40.00、HK$70.00、HK$70.00。另將單筆價格設為 HK$999,999,999,999.99，確認小計和個人明細可換行顯示。輸入 `1.001` 時，價格欄出現關聯錯誤並以錯誤摘要阻止有效結算；展開個人明細與「複製摘要」操作均成功。

窄屏檢查發現兩個排版問題並已在 `src/index.css` 修正：長姓名標籤不換行會撐寬文件；「全選／清除」按鈕和極長小計同列時會把按鈕文字擠窄。現在標籤可在長字串內換行，行動版小計另起一行，操作按鈕保持至少 44 × 44 px。修正後 320px 文件寬度仍為 320px，兩個 quick-action 按鈕皆為 44 × 44 px，小計完整留在容器內。

截圖位於 `output/playwright/`：`320-empty.png`、`320-mixed.png`、`320-large-final.png`、`390-mixed.png`、`390-large-final.png`。瀏覽器回報一個 `/favicon.ico` 404；沒有觀察到頁面 JavaScript 錯誤或主控台警告。
